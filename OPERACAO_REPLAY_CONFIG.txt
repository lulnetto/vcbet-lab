UBET - Replay e versionamento de config

Objetivo
- rodar snapshots históricos com múltiplas configs
- comparar o comportamento das picks geradas
- reconstruir uma baseline antiga sem depender de memória de chat

Configs disponíveis
- configs/champion_strict.json
- configs/intermediate_balanced.json
- configs/legacy_recovered.json

Fluxo recomendado
1) listar configs via API
   GET /configs

2) rodar replay de uma run histórica
   python3 replay_pipeline.py \
     --source-run-dir data/runs/2026-04-23/run_20260423_004727 \
     --config champion_strict \
     --config intermediate_balanced \
     --config legacy_recovered

3) abrir os arquivos gerados em data/replays/<data>/comparison_<run_id>/
   - comparison_summary.json
   - comparison_summary.csv

O que olhar primeiro
- overlap / jaccard com a run histórica
- picks_total
- picks_by_market
- discard_reason_counts no quality_report de cada replay

Nova execução normal com config explícita
- CLI:
  ./run_project.sh --mode full --date 2026-04-23 --config-name champion_strict
  ./run_project.sh --mode full --date 2026-04-23 --config-name legacy_recovered

- API:
  POST /jobs/analysis
  {
    "mode": "full",
    "date": "2026-04-23",
    "config_name": "legacy_recovered"
  }

Observação
- o fingerprint da config passa a ser salvo no quality_report e no run_manifest
- toda run nova grava strategy_config_snapshot.json dentro da pasta da run
